# Architecture rules
- Share fixed-contrast picture-arrow controls only between Custom X single/multi carousels, overlaid on the row edges without side gutters; this keeps branding, native swiping and other widget navigation independent.
- Scope neutral form interaction effects to the existing public embed document marker, including page scrollbars and portals; this keeps client branding and portal defaults independent.
- Scope Quote Estimator content-following phone sizing and step-scroll recovery separately from its visual themes; preserve legacy iframe scrolling and exclude V3 and other widgets.
- Keep Ring OS carat slider values separate from 0.50 catalogue/image buckets; this allows 24k quarter-carat choices without changing inventory, pricing, or image storage.
- Keep 24k Ring OS carat selection confirmation explicit and responsive: inline on desktop, popup on mobile; this prevents drag events from changing steps while preserving one slider model.
- Warm 24k Ring OS carat imagery after shape selection through a bounded, bucket-deduplicated queue; this keeps the visible image prioritized without competing with the ring viewer.
- Store Custom X custom-question short step names in each form's existing `step_labels` JSON map under `custom_q_<question_key>`; this preserves stable question keys without a schema change.
- Resolve Sandbox Quote Estimator versions through a single version-to-storage map while all other clients use V2 storage; this prevents cross-version writes and tenant leakage.
- Build every preview/test link or iframe for public forms through the shared embed URL helpers (getDiamondsFormUrl, getGrillBuilderUrl, getCustomEnquiryUrl), never relative `/embed-*` paths; portal routing on admin/vault redirects relative paths to the dashboard.
- Keep Sandbox Quote Estimator V3's conditional questions as separate stage keys while preserving existing answer fields and legacy draft-stage mapping; this avoids changing lead payloads or invalidating saved previews.
- Map Sandbox V3's saved `form_colors` to V3-scoped semantic variables while keeping its default palette in global CSS; this isolates customizable styling from V1/V2 and other clients.
- Bypass the embed referrer whitelist only for top-level test previews (Sandbox V3 and `?quoteTheme=` theme previews, which never write a lead); this lets shared preview links open while preserving restrictions on embedded and live forms.
- Keep Sandbox V3 estimates hidden until contact details are submitted while retaining internal pricing calculations and the existing post-contact result; this preserves lead-first quote disclosure.
- Render every client-branded customer email header through the shared branding helper using the client's explicit light/dark header preference; this keeps logo contrast consistent without touching notification data flow.
- Resolve Ring OS final action (deposit/full checkout/lead capture) through ring-os-diamond-checkout (client + _shared mirror) instead of changing stored pricing modes; this lets allowlisted accounts split checkout by diamond type without touching other clients or the admin Estimates option.
- Send admin marketing campaigns only through the marketing-* functions, the separate marketing sender, and the shared `marketing-email` renderer/scheduler (src/lib mirrored in supabase/functions/_shared); this keeps campaign reputation isolated from app/customer emails and makes preview and send produce identical HTML.
- Keep the marketing campaign minute tick scheduled only while a campaign is scheduled/sending (trigger wakes it, tick unschedules when idle); this avoids a permanent polling job.
- Apply Metal IQ volume tiers only through the mirrored `metal-offer-tiers` helpers (src/lib + supabase/functions/_shared) and the opt-in `volume_tier_config` column; NULL/disabled must leave every quote identical to the original single-rate math.
- Mark every lead-form contact field with standard autocomplete tokens (name/given-name/email/tel) inside a form element, and let the shared phone input split autofilled international numbers via phone-autofill; this keeps device autofill working without changing validation or payloads.
- Run diamond outlier scoring only from the admin "Run Score Now" button (trigger_diamond_pipeline -> diamond_pipeline_jobs, one step per diamond_pipeline_step call with a pause between steps, temporary `diamond-pipeline-job` cron that unschedules itself); uploads never start scoring and no nightly or minute tick may be re-added.
- Rebuild a client's Ring OS availability cache only on Confirm Catalog (refresh_client_diamond_availability) and as the last phase of a scoring run; keep compute_client_diamond_catalog_availability set-based (no per-row diamond_pool_row_matches scan) and never reinstate the 5-minute / 24-hour sweep.
- Keep the JewlX database backup weekly (weekly-jewlx-db-backup -> trigger_database_backup) and limited to the BACKUP_TABLES allowlist in supabase/functions/database-backup; diamond/gemstone pools, AI preview and log/analytics tables stay out, and cron commands read credentials from cron_config rather than embedding keys.
- Price Ring OS diamonds in GBP/CAD only from admin-approved FX versions (diamond-fx-sync-rates suggests rates; apply_diamond_fx_rates -> diamond_fx_step stages diamond_pool_fx_prices and publishes by switching diamond_fx_state, temporary `diamond-fx-price-job` cron unschedules itself, 200k rows per step); an FX run and a scoring run never start beside each other (guards in apply_diamond_fx_rates and trigger_diamond_pipeline); uploads never fetch or apply rates and no FX schedule may be added.
- Keep Ring OS catalogue currency (clients.ring_catalog_currency, USD/GBP/CAD) limited to the ring-os-currency allowlist (src/lib + _shared + SQL ring_os_currency_client_allowed, currently Sandbox); ring step prices are typed in that currency (price + price_usd/gbp/cad memory columns), never converted, and diamond preset logic changes go into get_diamond_presets_filtered_base, not its currency wrapper.
- Never let billing (stripe-webhook, check-subscription, admin-reconciliation, reconcile-client-stripe) write `clients.enabled_features`; every new client (Stripe Payment Link, create-client-user, and the clients.enabled_features column default) starts with every module explicitly off (MODULES_OFF_FEATURE_SET) and admins switch modules on by hand; this keeps a first payment from activating Ring OS / Custom X / Metal IQ.
- Gate widgets on the live Stripe status through `subscription_status_allows_widgets` only: past_due/unpaid/incomplete/paused/canceled are off from the first failed payment, invoice.paid syncs back to active to turn them on, a manual billing override still wins, and every public embed (Ring OS, Ring Builder/Quote Estimator, Grillz, Custom Enquiry, Metal IQ) must block on get_client_branding.subscription_active while keeping the admin module toggles untouched; no grace period or auto-pause cron.
